# 故障排查

[English](../troubleshooting.md) | **简体中文**

请从生成的 JSON 报告开始排查。报告中记录了结构化原因、候选身份、目标证据和清理证据，控制台输出可作为补充诊断信息。

## 任务启动前配置失败

使用相同参数加上 `--dry-run` 运行命令，并检查每一项必需值。生产 Pro-Lite 运行需要主机、远程根目录、镜像仓库、模型名称、模型 ID、提供商、远程模型端点、会话前缀以及一套完整的凭据传输方式。必须为绝对路径的路径会在 SSH 前遭到拒绝。

直接 Kimi coding 模式应使用经过验证的 G11 配置。`kimi-for-coding` 使用 262144-token 上下文并保留完整思考历史。`k3` 使用 1048576-token 上下文与 `reasoning_effort=high`。两套配置都要求使用 `openai` 提供商、`https://api.kimi.com/coding/v1` 端点，并要求受保护的环境文件已经存在于工作节点。

## 提供商探测或生成失败

检查共享模型健康记录与每项任务的生成指标。模型身份、端点身份、思考配置、上下文窗口、采样值和输出上限会分别接受检查。

身份验证失败与提供商配额耗尽都属于生成技术失败。此时，候选、unresolved 判定和官方评测结果字段保持未设置。仅在实验协议允许新一次任务启动时重试。

对于反向代理传输，请验证本地认证中继、SSH 隧道、远程中继健康端点、上游 URL 哈希和受保护的 token 文件。对于直接传输，请验证工作节点 DNS、HTTPS 连通性、凭据文件权限模式和精确的模型响应身份。

## 运行时同步失败

运行器会为同步的 OpenCollab 公开模块、OpenCollab-Eval 模块和打包资源创建清单。出现不匹配意味着工作节点执行的源代码树与控制器不同。

请先检查 `--remote-python`。解释器必须能够导入同步的运行时与全部所需提供商依赖。随后比较本地运行时树记录、远程预检记录以及生成前即时获取的树记录。

使用 `--no-sync-runtime` 时，必须通过 `--expected-runtime-tree-sha256` 提供此前精确验证过的 SHA-256。出现不匹配仍会停止运行。

## Docker 或镜像预检失败

验证 `docker info`、镜像可用性、不可变镜像 ID、配置的工作目录和运行范围内存储。单个镜像的失败仅影响对应任务或镜像。只有直接探测表明共享 Docker、存储、队列或运行时基础设施不可用时，才会暂停整个批次。

清理过程只会删除当前运行所有权记录涵盖的容器和进程。名称冲突或不受当前运行所有的容器会被报告并保留。

## 候选构造失败

检查生成指标、可信快照证据、候选投影和进程静止记录。

常见的任务级原因包括候选文件不可读、Git 无法表示的特殊文件、指向外部的符号链接、不可信的 Gitlink 替换、补丁过大、后台进程持续写入，或无法从可信基准重建候选树。

被忽略的缓存与日志会在打开前完成分类，并留在候选之外。候选身份由控制器持有，不受 Solver 修改 Git 配置、索引、引用、替换对象、忽略文件或属性的影响。

## 官方评测为 technical failed

读取任务报告中的 `technical_reasons` 与 `output_artifact_errors` 字段。分别检查源补丁 SHA、已评测补丁 SHA、候选预期、镜像身份、基准提交、目标计划、命令证据、证明产物和容器退出状态。

以下情况仍属于技术失败。

| 情况 | 原因 |
| --- | --- |
| 目标计划为空或不受支持 | 没有关于必要工作的可执行陈述 |
| 收集到零项测试 | 没有执行目标 |
| 缺少候选归因证据的导入或收集失败 | 目标结果未知 |
| 预期候选 tree 产生前的绑定源投影拒绝 | 候选属于 unresolved |
| 投影或 official worktree 应用失败 | 评测状态不一致 |
| 补丁 SHA 不匹配 | 生成与评测引用不同候选 |
| 日志缺失或不安全 | 无法验证目标证据 |
| 进程静止后的容器删除失败 | 运行告警 |
| 清理后仍未静止 | 仓库状态仍可能变化 |

结构化证据证明目标精确失败或跳过、候选引起构建、初始化、导入或依赖失败，或者生成阶段尚未记录预期候选 tree 时可信源投影拒绝绑定补丁，候选会被记为 unresolved。与预期 tree 冲突的源投影拒绝，以及评测准备基线上的拒绝，都属于技术失败。没有候选归因的非零命令仍属于技术失败。

## 结果似乎已经过时

比较任务 ID、实例 ID、记录 ID、运行 ID、完整补丁 SHA-256、运行时树 SHA-256、官方报告路径与报告哈希。只有相关身份和证据全部一致时才能复用。文件修改时间、缩短的哈希或目录中最新的报告都不足以证明这一点。

新运行应使用新的输出目录与远程基准目录。协议允许继续运行时，应保留恢复运行的身份与限制。

## 最终报告发布失败

`oc-eval final-report` 会在替换发布结果前验证完整任务清单与每个引用产物。请检查失败发布清单中的第一项验证错误或渲染错误。

任务缺失、任务重复、技术失败、数据集哈希不匹配、方法不匹配、报告哈希不匹配、直接执行证据不完整、产物路径不安全和 LaTeX 编译失败都会返回非零状态。后续尝试失败时，此前已经完成的发布仍保持原样。

## 收集支持材料包

只将运行范围内且已经脱敏的证据复制到源码检出之外的目录。材料应包含控制器提交、OpenCollab 提交、运行时树哈希、移除凭据后的命令、任务报告、生成指标、候选投影、官方报告、清理证据和最小范围的相关日志。

共享材料包前，请检查任务文本、补丁、轨迹、实例 ID、提供商元数据、主机名和文件系统路径。
