# G22 v3 文件证据

[English](../g22-file-evidence.md) | **简体中文**

`validation-council-dual-coder-selection-v3` 沿用 v2 的解题提示、A/B 执行顺序、机械选择、结构化裁决校验、默认采用 A 的规则和候选采用过程。裁决角色获得完整证据文件的引用，并通过 `read_candidate_evidence` 工具读取差异。v1 与 v2 的工作流注册保持原有行为。

可选工作流参数 `candidate_evidence_dir` 指定证据保存的父目录，建议位于运行的产物目录中。每次裁决都会建立独立子目录。省略该参数时，程序创建并保留系统临时目录，将其位置写入工作流日志。归档时应同时保存这个目录和工作流轨迹。

每个候选都保存逐字节对应的 UTF-8 `candidate.diff`、JSONL 索引和公开命令及测试记录。索引行记录原始路径、文本或二进制类型，以及完整差异中的字符范围。二进制补丁、权限变化、删除记录和缺少末尾换行的状态均保留在证据中。A/B 共用的公开记录另存一份文件。

工具在工作流宿主机读取已登记的证据。裁决环境即使位于隔离容器，也能通过工具访问这些文件。工具提供只读能力，可访问范围由这次裁决的证据集合决定。候选控制的文件名作为索引数据保存，与宿主机读取路径分开。

读取使用 Unicode 字符偏移，返回内容、`next_offset` 和 `eof`。单次响应最多返回 32,768 个字符，使工具消息保持适当大小，也覆盖只有一条巨大长行的文件。裁决角色可以继续读取，累计读取量没有上限。填写裁决结构时应引用索引中的原始变更路径。

这是显式的裁决输入版本更新。使用 v3 检查已有候选时，应保留旧结果与旧轨迹。新裁决只负责选择候选，基准成绩须在采用候选后，依据原测试和原资源完成评分才能报告。
