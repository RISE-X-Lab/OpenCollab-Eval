## 最终结果

OpenCollab G1.1 完整评测 100 题，通过 19 题，未通过 81 题。OpenHands 完整评测 100 题，通过 16 题，未通过 84 题。Claude Code 完整评测 100 题，通过 15 题，未通过 85 题。三套结果的最终技术失败均为 0。

三者共同通过 11 题，题号为 7、11、21、32、34、53、60、69、74、92、93。三者通过题目的并集为 23 题。完整百题上 G1.1 通过 19 题，OpenHands 通过 16 题，Claude Code 通过 15 题。三方通过并集的 23 题继续作为重点切片，用于分析各系统覆盖的重合与差异。

## 比较分析

三套系统使用同一个 GLM-5.2 模型，完整系统组合在 agent 结构、工具交互、上下文组织、候选筛选和执行方式上存在差异。完整百题上 OpenCollab G1.1 通过 19 题，通过范围最宽。它独立覆盖 35、36、43、46、47、50 六题，并与 Claude Code 共同覆盖 37。这个集合集中出现模块位置、公开接口、边界分类和回归兼容问题，G1.1 在这组跨模块任务上呈现更高的最终覆盖。

OpenHands 与 Claude Code 的重合度最高。OpenHands 的 16 道通过题中有 14 道也被 Claude Code 做出，两者共同而 G1.1 未通过的题是 33、55、70。Claude Code 在双方共同通过的 12 题中做出 11 题，只在第 75 题留下一个真实保留测试回归。两种完整系统组合在这批题上的通过集合高度重合。

Claude Code 在完整 100 题中通过 15 题，另外 85 题未通过。三套系统拥有相同的百题分母，可以直接比较 19%、16% 和 15% 的最终覆盖。三方通过并集的 23 题中，Claude Code 通过 15 题，这个切片用于解释重合结构。本次比较没有控制提示、上下文长度、token 预算、重试策略、候选选择和执行环境。现有数据说明三种系统组合的最终覆盖差异。组件级因果判断需要在统一设置下完成受控消融。

第 35、43、78 题在追加评测后归入未通过。第 35 与 78 题的候选自身把实现放在错误模块或错误公开接口，公开目标在导入阶段无法执行。第 43 题的原始补丁只修改测试文件，过滤后没有生产代码候选。三题保留零目标和空补丁证据，同时以最终解题能力归为未通过。
